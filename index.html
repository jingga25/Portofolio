Construction Procurement & Tender System
Project budgeting · Owner Estimate · Competitive & direct-appointment tender · Multi-tier approval
Enterprise ERP

Redesigned the goods and services procurement flow for a national-scale construction company — covering project budget creation from purchase requests, multi-supplier tendering with multi-winner capability, and approval flows where budget and supplier proposals move forward together yet can still be decided independently when needed.

Formulated financial calculation logic that was a recurring source of errors in the legacy system: the correct sequencing of tiered discounts (per item, per order, per total), determining the proper tax base before VAT is calculated, and handling shipping costs and warranty retention.

Corporate Asset Transfer Management
Bulk asset transfer across owners · Depreciation correction · Journal integration with the finance system
Asset Management

Built a bulk asset transfer feature allowing a single transaction to move many assets from several previous owners to several new owners at once — replacing a manual one-by-one process previously prone to human error during employee resignation or department transfers.

Designed an accounting correction mechanism for assets incorrectly classified as depreciable. Core design principle: history is never deleted, only reversed through a reversal journal entry — keeping the audit trail complete and traceable at any time.

Business Process Design Approval Workflow API Integration Spec Audit Trail Design

Simplifying Approval for Split Tender Awards
Automatic grouping by contractor & tender · Approval corridor still anchored to the original tender value
Approval Workflow

Designed a solution for cases where a tender awarded to one contractor gets split into many work-order documents due to per-document quantity limits — previously forcing approvers to approve the same business decision repeatedly. Solution: the system automatically groups documents by tender + contractor combination, with the option to approve an entire group at once or still act on a single document when an approver needs to hold one back selectively.

The hardest part: ensuring the approval-authority corridor still references the original tender value before it was split — not the value of each resulting document — to close a loophole where a high-value tender could slip through to a lower approval tier simply because it was broken into smaller pieces. Also designed a dual approval channel (dashboard and email) with race-condition handling when an approver acts from both channels simultaneously.

User Flow User Story (Agile) Acceptance Criteria Interactive Wireframe Multi-Channel Approval Design
→Reduced repetitive approval workload without loosening value control — decisions are still evaluated at the actual transaction scale.
End-to-End Non-Formal Purchase (Petty Cash) Request Flow
Requests without formal purchase documents · Voucher & realization integration with the finance system
Process & Systems Design

Designed an end-to-end low-value purchase request flow that runs without a formal purchase document — from the initial request, maximum-value validation and split-transaction detection, tiered approval, fund voucher issuance to the finance system, through matching received goods against the original request and closing realization.

Established key validation rules that were previously vulnerable to manual manipulation: received quantity can never exceed the requested quantity, any volume/type discrepancy requires a written explanation, and a single proof of payment cannot be used for more than one request. Also produced a complete technical spec (API endpoints, request/response schemas, database impact, and logic flow) so the development team could execute directly without additional clarification sessions.

User Flow User Story (Agile) Acceptance Criteria Interactive Wireframe API & Database Spec Cross-System Integration
→Closed a control gap on small, high-volume transactions — an area often overlooked for being low-value per transaction, despite significant cumulative risk.
